# How SecureTrace AI Works (Simple & Easy Guide)

Welcome to the project documentation for **SecureTrace AI — Document Watermarking Lab**! This guide is written in plain, everyday language to help anyone (students, professors, project evaluators, or developers) easily understand what this system does, how it works under the hood, and why each part is built the way it is.

---

## 1. What is SecureTrace AI?

Imagine you work at a company or a university and need to share a sensitive PDF or image with someone (like a contractor, student, or client). If that person leaks the document on the internet:
- How do you know which copy was leaked?
- How do you prove who received it?
- How do you verify if the file was modified?

**SecureTrace AI** solves this problem by:
1. **Embedding real watermarks** into documents (both visible and invisible).
2. **Personalizing the watermark** with a specific recipient ID (e.g. `CONFIDENTIAL | SHARED WITH USER-102`).
3. **Calculating a cryptographic fingerprint (SHA-256 hash)** before and after watermarking.
4. **Recording every action in an audit ledger database** so there is a permanent audit trail.
5. **Providing a verification tool** to check leaked or shared files and extract the hidden watermark.

## 2. The 3 Types of Watermarks (Explained Simply)

| Type | How It Looks to a Human | How It Works Under the Hood | Best Used For |
| :--- | :--- | :--- | :--- |
| **Visible Watermark** | Clear text across or on the corner of the page. You can customize font size, color, angle, and opacity. | The server takes your file and permanently draws the text into the PDF stream or into the image's pixels. When downloaded, the watermark stays forever—it's not just a fake CSS trick on a webpage. | Discouraging unauthorized distribution, company branding, and public copyright notice. |
| **Subtle Watermark** | Very faint, light text (e.g., 10%–15% opacity). Readers can still easily read the document without being distracted. | Same real rendering as visible watermarking, but with low transparency so it blends into the background. | Official internal reports, research papers, and executive memos where high readability is required. |
| **Invisible Watermark (LSB Steganography)** | Looks 100% like the normal, original picture! The human eye cannot see any difference at all. | Uses a genuine computer science technique called **Least Significant Bit (LSB)** insertion on PNG images. It hides binary 0s and 1s of the text in the tiny last bits of the red, green, and blue color numbers. | Covert tracking. If someone leaks the picture, you run it through the Verification Lab, and the secret recipient text is extracted from the pixels! |

> **Note on Invisible PDF Watermarks:** We do **not** claim to support invisible PDF watermarking yet. In academia and engineering, putting text into hidden PDF tags is just metadata (which is easily deleted), not genuine invisible content steganography. We mark this honestly as a *Future Research Capability*.

## 3. Step-by-Step: What Happens When You Watermark a File?

Here is the exact journey from clicking upload to downloading the protected file:

```
[ User Browser ]
       │
       ▼ (1. Select File: PDF or Image)
[ Frontend Validation: Checks size < 25MB and format ]
       │
       ▼ (2. Click "Apply Watermark")
[ Sent via multipart/form-data HTTP request ]
       │
       ▼
[ FastAPI Backend Server ]
       │
       ├─► (3. Calculates Original SHA-256 Hash of your file)
       │
       ├─► (4. Applies the Real Watermark Engine):
       │      • If PDF: PyMuPDF draws text into all page streams.
       │      • If Image (Visible): Pillow blends alpha text into pixels.
       │      • If Image (Invisible): Pillow embeds LSB bitstream into RGB bytes.
       │
       ├─► (5. Calculates Watermarked SHA-256 Hash of the output)
       │
       ├─► (6. Saves file securely in backend/storage/watermarked/)
       │
       └─► (7. Writes an audit record to SQLite database: securetrace.db)
       │
       ▼ (8. Response sent back to browser)
[ Frontend displays live preview, hashes, and provides Download button ]
```

## 4. What is the SHA-256 Fingerprint & Activity Ledger?

### What is a SHA-256 Hash?
Think of a SHA-256 hash as a digital fingerprint. It is a 64-character code (like `70e5c0bbed36f38f16e...`) generated by a mathematical formula:
- If even a single dot or letter in a file changes, the entire fingerprint completely changes!
- In SecureTrace AI, we compute the fingerprint **before** watermarking and **after** watermarking.

### Does a changed hash mean the file is corrupted or hacked?
**No!** Because watermarking actually adds text or modifies pixels, the file's bytes have legitimately changed. The changed hash simply proves that the watermark was successfully applied.

### Why do we have an Activity Ledger?
Every time a file is watermarked or verified, an entry is saved in a local SQLite database (`backend/securetrace.db`). It records:
- Date & time
- File name
- Original hash vs. watermarked hash
- Watermark text & recipient ID
- Status (Processed or Verified)

> **Important:** This is a conventional, fast database audit ledger. It is **not** a blockchain, and we do not falsely label it as one.

## 5. How Does Watermark Verification Work?

If you find a document or image and want to know where it came from:
1. Go to the **Watermark Verification** tab in the dashboard.
2. Upload the suspicious or watermarked file.
3. (Optional) Type what watermark text you expect (like `USER-102`).
4. Click **Verify Document**.

### What the server does:
- **For Invisible LSB Images:** The server reads the least-significant bit of each pixel, collects the binary bits, and reconstructs the hidden message. If it finds the `SECURETRACE::...::END` marker, it displays the extracted text and marks the status as **DETECTED**!
- **For PDFs:** The server uses PyMuPDF to inspect the document's content streams for the watermark signature.
- **Result Output:** The system will honestly tell you if the mark is **DETECTED**, **NOT DETECTED**, or **UNABLE TO VERIFY** (with technical notes explaining why).

## 6. How the System is Built (Technologies Used)

We used 100% free, open-source technologies with no paid APIs and no Docker:

- **Frontend (What you see):**
  - **React + Vite**: Fast, modern web interface.
  - **JavaScript (ES6+)**: Clean, standard browser code without complex TypeScript overhead.
  - **Tailwind CSS v4**: Styled like a dark navy enterprise cybersecurity tool.
  - **Lucide React**: Clean icons for security, files, and dashboards.

- **Backend (The engine):**
  - **Python FastAPI**: A lightweight, high-performance web framework.
  - **PyMuPDF**: The industry-standard Python library for manipulating real PDF page structures.
  - **Pillow (PIL)**: Python library for processing image pixels, transparency, and LSB bits.
  - **SQLite**: Built-in, zero-configuration database that saves your history in a file named `securetrace.db`.

## 7. Quick Summary for Project Presentations / Viva

When explaining this project to an evaluator or teacher, you can summarize it in 4 points:

1. **Problem:** Document leaks are hard to trace without permanent, tamper-evident identifiers.
2. **Solution:** SecureTrace AI embeds client/recipient identifiers directly into the content of PDFs and images on the server side (not just CSS on the screen).
3. **Innovation:** Combines visible branding, subtle attribution, and invisible LSB image steganography with a cryptographic SHA-256 audit ledger.
4. **Reliability:** Built with Python FastAPI, PyMuPDF, Pillow, React, and SQLite—runs entirely on a local machine with zero external cloud dependencies.
